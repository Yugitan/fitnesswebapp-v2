# 小白Amax Figma 原型设计提示词

> 用途：复制到 Figma AI，生成一套可以进入前端开发的手机端高保真界面稿。  
> 产品方向：动作展示库 + 健身训练记录。  
> 设计目标：只专注手机端 Web App / PWA，弱化品牌露出，做成高级、克制、真实可用的运动训练工具。

---

## 可直接复制给 Figma AI 的提示词

请为一个手机端健身 Web App / PWA 设计一套高保真 UI 原型。产品暂名「小白Amax」，但不要把品牌名做成强营销主视觉，只在设置页或顶部小标识中轻量出现。

这个产品只解决两个核心问题：

1. 查看动作：搜索动作、筛选动作、查看动作 GIF、阅读中文动作步骤。
2. 记录训练：添加动作、记录每组重量和次数、查看历史训练。

不要设计 AI 私教、社区动态、课程售卖、排行榜、登录注册、付费订阅、会员权益、营销落地页。

请输出一套「可开发的产品界面稿」，不是概念海报，也不是泛泛的 App mockup。每个页面都要有真实控件、真实数据状态、清晰导航、明确空状态和可执行按钮。

---

## 设计方向

整体气质参考 Nike Training Club、Nike Run Club、Apple Fitness 的高级运动感：干净、有力量、信息明确、操作直接。可以学习它们的视觉节奏、留白比例、强标题、数据呈现和高对比按钮，但不要复制 Nike / Apple 的 logo、品牌图形、专有文案、页面结构或标志性符号。

请避免常见 AI 原型感：

- 不要做成一堆圆角大卡片漂浮在渐变背景上。
- 不要使用大面积紫蓝渐变、玻璃拟态、霓虹光晕、装饰性圆球。
- 不要堆砌无意义的欢迎语、宣传语、空泛说明文案。
- 不要让页面像 SaaS 后台、运营看板、健身房广告海报或低成本 demo。
- 不要把所有模块都做成同样大小、同样圆角、同样阴影的卡片。
- 不要使用过度可爱的插画、emoji 图标、卡通人物。
- 不要让英文动作名成为主要标题。
- 不要在动作详情页把小尺寸 GIF 放进超宽深色舞台，导致左右留白很大。

期望关键词：

- 高级运动 App
- 移动端优先
- 高对比
- 干净克制
- 快速操作
- 数据清晰
- 真实训练场景
- 可开发
- 有力量感但不过度装饰
- 专业用户也愿意长期使用

## 用户层级

界面需要同时服务三类用户：

1. 健身小白：能快速理解动作怎么做，知道该点哪里开始记录。
2. 有训练经验的人：能高效搜索动作、添加动作、输入组数、重量、次数。
3. 教练或专业用户：能快速回看训练历史、训练量、动作分布和单次训练明细。

因此设计要做到：

- 信息表达直观，不依赖复杂术语。
- 记录流程足够快，不要让用户在训练中多次跳转。
- 动作详情页要像专业动作图鉴，GIF 和步骤是核心。
- 历史页要有可扫读的数据密度，但不要变成后台表格。

## 设备与画板

请只设计手机端，不要设计桌面端、平板端或响应式大屏页面。

画板尺寸：

- iPhone 15 Pro：393 × 852

手机端要求：

- 使用固定底部导航，4 个主入口：今日、动作库、记录、历史。
- 设置入口放在顶部图标或个人/更多入口中，不占底部主导航。
- 底部导航高度稳定，内容区域必须避开底部导航。
- 主要按钮高度不低于 44px。
- 搜索、筛选、添加动作、记录组数都要适合单手操作。
- 关键操作放在拇指容易触达的位置。
- 训练记录页和动作详情页可以使用底部固定主操作按钮。
- 所有页面都要考虑 iOS Safari 底部安全区，不要让按钮或输入框贴到屏幕底部。
- 不要出现桌面端侧边栏、顶部宽导航、大屏分栏布局或超宽内容区。
- 设计语言要像原生 App，而不是普通网页表单。

## 视觉系统

请使用黑白灰作为主体，少量高能量强调色表达行动和训练状态。

推荐色板：

- 主背景：`#F7F7F2` 或 `#FFFFFF`
- 页面主文字：`#111111`
- 次级文字：`#737373`
- 弱提示文字：`#A3A3A3`
- 卡片背景：`#FFFFFF`
- 深色重点面板：`#181818`
- 主行动色：`#FF4D1C`
- 运动完成/PR 强调：`#C6FF00`
- 边框：`#E6E6E1`
- 危险操作：`#D92D20`

使用规则：

- 主界面保持白色或近白底，不要整站全黑。
- 深色面板只用于首页今日摘要、训练中的状态面板或重点数据区。
- 橙红只用于主按钮、当前选中状态、关键数据点。
- 荧光黄绿只用于非常少量的完成状态、PR、训练标记。
- 卡片阴影极轻，主要靠边框、色块、字号和间距建立层级。
- 不要使用柔和粉橙渐变、紫蓝渐变、玻璃拟态或彩色光晕背景。

字体：

- 中文系统字体：PingFang SC / Noto Sans SC / Microsoft YaHei。
- 页面标题：26px 到 34px，700 或 800。
- 关键数字：28px 到 40px，700 或 800。
- 区块标题：17px 到 20px，700。
- 卡片标题：15px 到 17px，600 或 700。
- 正文：14px 到 16px。
- 辅助信息：12px 到 13px。
- 不要使用负字距。
- 不要使用 viewport width 控制字体大小。

形状：

- 卡片圆角：8px。
- 按钮圆角：8px。
- 输入框圆角：8px。
- 小标签圆角：999px。
- 不要把所有模块都做成超大圆角胶囊。

图标：

- 使用 Lucide 风格线性图标。
- 图标按钮必须有明确点击区域。
- 常见操作请用图标：返回、搜索、筛选、收藏、删除、复制、编辑、下载、上传、设置。
- 不要用 emoji 作为正式 UI 图标。

## 内容与中文规则

所有用户可见的动作名称必须使用中文作为主标题。

动作示例：

- 四分之三仰卧起坐
- 45度侧屈
- 空中自行车
- 四足蹲姿拉伸
- 弹力带窄握下拉
- 哑铃侧平举
- 杠铃卧推
- 自重深蹲

英文名只能作为动作详情页的弱辅助信息，不得作为列表卡片主标题。

肌群、器械、部位必须显示中文：

- 目标肌群：腹肌
- 协同肌群：腹斜肌、髋屈肌、下背
- 器械：自重
- 部位：核心

动作步骤只显示中文，不要设计中文 / EN 语言切换控件。

文案要短、直接、像工具产品：

- 开始记录
- 添加动作
- 复制上一组
- 完成训练
- 查看详情
- 导出 JSON
- 导入 JSON

不要写大段宣传语，不要写「开启你的蜕变之旅」这类营销文案。

## 建议页面结构

请设计 6 个核心页面，保留真实开发需要的流程，减少不必要页面。

1. 今日
2. 动作库
3. 动作详情
4. 记录训练
5. 训练历史
6. 设置

训练详情可以作为「训练历史」中的详情状态或二级页面呈现，不必单独做成复杂独立模块；如果画板空间充足，可补充一个训练详情画板。

---

## 页面 1：今日

目标：用户打开后立刻知道今天是否训练过，并能快速进入记录训练或动作库。

1. 顶部
   - 小号品牌标识：小白Amax 或 Amax
   - 主标题：今日训练
   - 右侧设置图标

2. 今日状态面板
   - 使用深色运动面板，视觉有冲击力但高度克制。
   - 显示日期。
   - 显示状态：
     - 未训练：今天还没记录训练
     - 已训练：今天已完成训练
   - 显示 3 个关键数据：
     - 动作数
     - 总组数
     - 总训练量
   - 主按钮：开始记录
   - 次入口：浏览动作库

3. 快捷操作
   - 搜动作
   - 记训练
   - 看历史
   - 每个入口用紧凑按钮或横向操作条，不要做成大白卡片堆。

4. 最近训练
   - 只显示有动作的训练记录。
   - 不显示 0 动作、0 组、0 kg 的空记录。
   - 每条记录展示：日期、动作数、组数、训练量、部位标签。

---

## 页面 2：动作库

目标：快速找到动作，卡片清晰展示中文动作名、部位、器械和动作缩略图。

布局：

1. 顶部标题
   - 标题：动作库
   - 辅助信息：1,324 个动作
   - 右侧：筛选图标

2. 搜索框
   - placeholder：搜索动作、部位或器械
   - 搜索框宽度与内容区对齐。
   - 搜索框固定在标题下方，不要做成过小图标入口。

3. 筛选
   - 部位：全部、胸部、背部、腿部、肩部、手臂、核心、有氧
   - 器械：全部器械、自重、哑铃、杠铃、绳索、壶铃、固定器械
   - 使用横向滚动 chip。
   - 选中态使用橙红，未选中使用白色或浅灰。

4. 动作卡片
   - 使用双列卡片。
   - 图片区域保持 1:1。
   - 图片应像动作图鉴，不要像电商商品图。
   - 右上角收藏图标。
   - 主标题只显示中文动作名，最多 2 行。
   - 标签显示部位和器械。
   - 图片和标题距离紧凑，减少无意义留白。

卡片示例：

- 标题：四分之三仰卧起坐
- 标签：核心、自重

---

## 页面 3：动作详情

目标：用户能快速看清动作怎么做，并能立刻加入今日训练。

这是整套设计的重点页面。请把 GIF 演示区当作核心内容，不要做成装饰区。

布局：

1. 顶部栏
   - 返回按钮
   - 动作中文名
   - 收藏按钮
   - 辅助信息：核心 · 自重

2. GIF 演示区
   - 使用紧凑 1:1 或接近 4:3 的媒体框。
   - 媒体框宽度跟内容区一致。
   - 如果 GIF 素材本身是 180 × 180，则媒体框接近方形，内部图像尽量填满可视区域。
   - 不要放进超宽横幅。
   - 不要做深色大舞台。
   - 不要出现巨大左右留白。
   - 背景使用白色或极浅灰，强调动作图像本身。
   - 图片边缘与容器边缘保持 8px 到 12px 内边距。
   - 下方以弱文字显示：© Gym visual。

3. 动作信息
   - 使用紧凑信息列表，不要用大表格。
   - 左侧字段名，右侧中文值。
   - 字段：
     - 目标肌群
     - 协同肌群
     - 器械
     - 部位

4. 动作步骤
   - 标题：动作步骤
   - 只显示中文步骤。
   - 每一步使用编号圆点 + 简短文案。
   - 步骤区要易读，但不要占用过多首屏空间。

5. 底部操作
   - 主按钮：加入今日训练
   - 固定在底部安全区上方。

---

## 页面 4：记录训练

目标：训练中快速添加动作、填写组数、重量和次数。

布局：

1. 顶部栏
   - 返回
   - 标题：记录训练
   - 完成

2. 日期
   - 使用简洁日期选择器。
   - 编辑历史训练时可显示日期，但不要抢主视觉。

3. 摘要条
   - 动作数
   - 总组数
   - 总训练量
   - 使用紧凑统计条，不要巨大卡片。

4. 动作记录卡片
   - 每个动作一块清晰区域。
   - 左侧缩略图。
   - 中文动作名。
   - 部位 · 器械。
   - 右侧删除图标。
   - 区域之间要有明确分隔，训练中扫一眼能看懂。

5. 组数据
   - 列：组、重量 kg、次数、操作。
   - 输入框高度适合手指点击。
   - 支持复制上一组。
   - 支持删除组。
   - 添加一组按钮放在动作卡片底部。
   - 不要让表格横向溢出；必要时使用紧凑列宽和图标按钮。

6. 添加动作
   - 使用明显的「添加动作」按钮。
   - 点击后打开底部抽屉。
   - 抽屉内包含搜索框、筛选 chip、动作列表。
   - 动作列表中显示缩略图、中文动作名、部位、器械。

---

## 页面 5：训练历史

目标：回看已完成训练，不展示空记录。

布局：

1. 顶部
   - 标题：训练历史
   - 辅助信息：本地记录

2. 本月统计
   - 本月训练次数
   - 总组数
   - 总训练量
   - 可以使用一条紧凑数据带。

3. 日历
   - 简洁月历。
   - 有训练的日期显示橙色点或橙色底。
   - 不需要复杂热力图。
   - 今天日期要有明确视觉标记。

4. 历史列表
   - 只显示有动作的训练。
   - 每条记录展示：日期、动作数、组数、训练量、部位标签。
   - 点击进入训练详情。

5. 训练详情状态
   - 标题：训练详情
   - 返回按钮表达为回到上一页，不要固定写回历史页。
   - 显示动作数、总组数、总训练量。
   - 列出每个动作的中文名、部位、器械和每组记录。
   - 每组格式：第 1 组，40 kg × 10 次。

---

## 页面 6：设置

目标：清楚告诉用户数据在本地，并提供导入导出。

布局：

1. 数据状态
   - 文案：训练记录保存在当前设备
   - 显示训练记录数量
   - 显示最近备份时间，如果没有备份则显示：尚未导出

2. 数据操作
   - 导出 JSON
   - 导入 JSON
   - 清空本地数据
   - 清空本地数据使用危险色，并需要确认状态。

3. 关于动作素材
   - 动作数据来源
   - 媒体归属：© Gym visual

设置页要像工具页，不要做成个人中心、会员中心或品牌介绍页。

## 组件状态

请至少体现以下状态，方便开发落地：

- 主按钮、次按钮、危险按钮。
- 搜索框默认态和输入态。
- 筛选 chip 默认态和选中态。
- 动作收藏默认态和已收藏态。
- 空训练状态：今天还没记录训练。
- 已训练状态：今日已有动作和训练量。
- 记录训练中的动作卡片。
- 添加动作底部抽屉。
- 历史列表有数据状态。
- 清空数据确认状态。

## 关键验收标准

请确保设计稿满足：

- 整体像高级运动 App，而不是 AI 生成的通用模板。
- 首屏像真实 App，底部导航、固定按钮、安全区都合理。
- 不要输出桌面端、平板端、宽屏布局或响应式大屏设计。
- 动作库卡片主标题全中文。
- 动作详情页所有肌群、器械、部位都中文。
- 动作详情页没有语言切换。
- 动作详情页 GIF 区域紧凑、清晰、不留巨大空白。
- 训练记录页可在训练中快速输入重量和次数。
- 首页和历史页不展示 0 动作、0 组、0 kg 的空记录。
- 页面不是营销页，不是后台，不是海报。
- 页面边距、导航、内容区、底部操作对齐统一。
- 所有按钮文字不能溢出容器。
