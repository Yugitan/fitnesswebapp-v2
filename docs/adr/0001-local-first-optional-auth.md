# ADR-001：本地优先 + 首版不强制登录

**日期**: 2026-07-22  
**更新日期**: 2026-07-26  
**状态**: 已决定  
**决策者**: 产品设计阶段

---

## 背景

小白Amax 当前方向已收敛为动作展示库和健身训练记录。用户在训练中最需要的是快速查动作、快速记录、弱网可用。

国内健身类 App 普遍要求注册登录才能使用，这对学生和新手的冷启动体验是显著障碍。首版如果引入登录、云同步和后端，会明显增加开发复杂度，也会推迟动作库和训练记录闭环上线。

## 决策

**采用本地优先（Local-First）架构，MVP 不做强制登录和云同步**：

- 动作库：静态加载 `exercises.json`，在浏览器本地搜索和筛选
- 训练记录：保存到浏览器 IndexedDB
- 收藏动作、最近动作、设置：保存到 IndexedDB
- 数据安全：提供导出/导入能力，明确提示数据保存在本设备
- 后续若需要跨设备同步，再引入登录和云端合并策略

## 替代方案

### 方案 B：强制注册登录 + 云同步
- 优点：架构简单，数据一致性有保障
- 缺点：启动流失率高，开发周期变长，偏离首版核心价值

### 方案 C：从首版开始做完整后端 API
- 优点：后续扩展空间大
- 缺点：对当前动作库和训练记录闭环不是必需项，维护成本更高

## 影响

- 前端需要实现 IndexedDB 数据层
- 首版无需 Supabase、FastAPI、鉴权和同步队列
- 用户更换设备或清理浏览器数据会丢失记录，因此必须提供导出/导入
- 后续加入云同步时，需要设计本地数据与云端数据的合并协议
